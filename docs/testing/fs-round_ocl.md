## 4. ข้อจำกัดที่รู้แล้ว ไม่ต้องเปิด issue

| เรื่อง | สถานะ |
|---|---|
| อีเมลไม่ออกจาก server จริง | ทุกอีเมลเข้าคิว outbox จนกว่าจะได้เครื่องส่งอีเมล (A6) |
| ข้อมูล HURIS SUPREME เป็นข้อมูลตัวอย่าง | รอ API จริง (A4) · ชื่อในวงเล็บเหลี่ยมคือชื่อสมมติ |
| ลายมือชื่อดิจิทัลบน Skill Transcript | บริการตัวอย่าง ยังไม่มีผลทางกฎหมาย |
| R12 คอลัมน์ตามข้อมูลที่ระบบมี | รอแบบฟอร์ม Excel ของ TOR 6.1 · ชีต 7–8 รอข้อมูลสหกิจจาก SUPREME |
| R07 R08 ส่งออก PDF แทน Word | รอยืนยัน (คำถามใน `98-customer-questions.md`) |
| ปุ่มแจ้งเตือนไม่แสดงจำนวนผู้รับก่อนกดส่ง | แสดงหลังส่ง · บันทึกใน BRD 05 US-M5-03 |
| หน้าแรกใช้ภาคล่าสุดเสมอ | ยังไม่มีตัวกรองปีการศึกษา ภาค และมุมมอง · บันทึกใน BRD 00 US-G-01 |
| ลิงก์ลืมรหัสผ่านไม่แสดง | แสดงเมื่อ PM ตั้งลิงก์บริการบัวศรีไอดีใน `FORGOT_PASSWORD_URL` |
| ค่าที่เป็นสมมติ | รหัส 10 นาที · ขอรหัส 5 ครั้งต่อชั่วโมง (C12) · เป้า 70% (C11) · Ethics ≥ 2.50 = S |

เจออาการที่ไม่อยู่ในตารางนี้ ให้เปิด issue ตามข้อ 10 ของ `test-manual_ocl.md`

## 5. เกณฑ์ปิดรอบ

1. ไม่มี "ไม่ผ่าน" ที่ความสำคัญ **สูง** ในทุกหมวดของรอบนี้
2. issue วิกฤตและสูงปิดหมด หรือ PM ลงชื่อยอมรับความเสี่ยงในหมายเหตุ
3. กรณี "บล็อก" ทุกตัวมีเหตุผลและรหัสกรณีต้นทาง และไม่เกิน 5% ของกรณีในรอบนี้
4. ทุกกรณีที่ผ่านมีผลจริงเป็นข้อความหรือตัวเลขที่ตรวจซ้ำได้ ไม่ใช่แค่คำว่า "ผ่าน"

หลังปิดรอบ PM สรุปผลเป็น `fs-round-result_ocl.md` (จำนวนผ่าน/ไม่ผ่าน/บล็อกต่อหมวด · issue ที่เปิด · เรื่องที่ต้องถามลูกค้าเพิ่ม)
